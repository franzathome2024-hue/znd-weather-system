# Fix Temperature Viewer UI Bugs

Branch: `fix/ui-bugs-map-alignment-overlay` → target `main`
Temperature-only release; no Wind, Rain, or Meta/Facebook changes.

## Summary of changes

### Bug 1 — Map style loading race condition (file: `public/app.js`)

**Root cause:** The previous code called `map.addSource()` and `map.addLayer()` inside a single `map.on("load", ...)` handler without checking whether the sources/layers were already registered. This threw "Source with id 'municipalities' already exists" whenever MapLibre fired `style.load` a second time (e.g. after a future `setStyle` call, a hot-reload, or a race between the initial `load` event and `renderMap()` being invoked from the `Promise.all` resolution). In addition, `renderMap()`, `renderPointCenters()`, and `renderPointMarkers()` called `map.getSource(...)` / `map.addLayer(...)` before the style was fully loaded, producing intermittent "Style is not done loading" errors.

**Fix:**
- Added a `mapLayersInstalled` flag guarded by an idempotent `installOverlay()` function.
- Added a `style.load` listener that resets the flag and re-installs sources/layers, so future style reloads never double-register.
- Added `mapReady()` helper and `isStyleLoaded()` checks in `renderMap()`, `renderPointCenters()`, and `renderPointMarkers()`.
- Every `addSource`/`addLayer` call is now guarded by `!map.getSource(id)` / `!map.getLayer(id)`.

### Bug 2 — MODELS and SPREAD column alignment (files: `public/styles.css`, `public/index.html`)

**Root cause:** The default auto table layout computed column widths independently from header vs body when model-name cells wrapped or when the Spread column contained wide "±x.x" values. The result was headers not lining up with their body columns on narrower viewports.

**Fix:**
- Switched both tables to `table-layout: fixed` with `overflow: hidden; text-overflow: ellipsis; white-space: nowrap;` on cells.
- Added explicit `<colgroup>` blocks to `#allTable` and `#modelTable` in `index.html` so header and body share the same column template.
- Column widths tuned for desktop with a media query tightening them under 480 px.

### Bug 3 — Temperature overlay alignment & opacity (files: `scripts/build-approx-geojson.mjs`, `public/data/zamboanga_del_norte_approx.geojson`, `public/app.js`)

**Root cause:** The Voronoi approximation GeoJSON was a quick strip-based hack with coordinates that ballooned to hardcoded raster edges (lon 121.8–124.0, lat 7.0–9.0) instead of ending at municipality boundaries. This caused polygons to stretch far outside the province (especially Baliguian/Sibuco/Godod on the west/north edges). The map also used a hardcoded `center: [122.85,8.1], zoom:8` rather than fitting to the data, so the overlay appeared misaligned with the basemap on first paint. The 0.7 fill opacity and black outlines then hid the basemap tiles entirely.

**Fix:**
- Rewrote `scripts/build-approx-geojson.mjs` as a proper rasterize + wall-follower contour tracer (clockwise edge stitching with rightmost-turn preference, small-component cleanup to remove discretization artifacts, 3-cell raster padding so no municipality touches the grid edge, corner → lon/lat conversion corrected for the pad).
- Regenerated `public/data/zamboanga_del_norte_approx.geojson`: 27 features, 98 KB, every polygon contains its verified centroid (27/27 point-in-polygon test passes), coordinates are `[lon,lat]` (CRS84), and every feature carries a `disclaimer: "NOT an official administrative boundary..."`.
- `initMap()` now calls `map.fitBounds(geoBounds(state.geo), { padding: 16, maxZoom: 9.5 })` after installing the overlay so the choropleth is always geographically registered with the OSM basemap on first paint.
- Reduced choropleth `fill-opacity` from 0.7 to **0.55** (0.75 on hover), softened `fill-outline-color` to `rgba(0,0,0,0.15)`, and reduced `muni-line` opacity to 0.75. Roads, labels, and coastlines on the basemap are now visible under the temperature colors without sacrificing readability of the choropleth.

### Cleanup
- Removed residual GADM 4.1 references from attribution copy in `app.js` and `index.html` (GADM was replaced by the Voronoi approximation in the previous correction pass; the old strings were stale).
- Added 5 new regression tests in `test/ui-fixes.test.js` covering: 27 valid polygons with centroids inside, CRS84 [lon,lat] ordering, colgroup presence, `table-layout: fixed`, and map style-reload guards.

## How to test manually
1. `npm run dev` and open the dev URL.
2. Confirm the map shows the OSM basemap with translucent colored polygons that follow the Zamboanga del Norte coast, with roads/labels visible underneath.
3. Resize the window across desktop / tablet / mobile portrait/landscape; confirm the "Location / Low / High / Models / Spread" headers line up pixel-perfectly with their rows, and the "Model / High / Low" columns in the per-model panel do the same.
4. Resize the browser or trigger a reload; confirm no "Source already exists" / "Style is not done loading" errors in the console.
5. Toggle between Tmax / Tmin / Spread; colors update, polygons stay in place.
